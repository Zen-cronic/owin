Why it exists

I built Owin because a buyer’s security questionnaire asks whether your AI providers keep customer data, and the true answer differs per endpoint.

Owin reads the vendor’s own page and marks each answer per endpoint:

  • Not true
  • Outdated
  • Needs review
  • Not stated
  • Verified

Three guided paths, about a minute each

  1. 1 Replay a real change Lumen Notes (fictional) wrote its answers on Sep 1, 2026. Answer 3 is not true for /api/crm-sync, because Anthropic’s MCP connector is outside ZDR; answer 5 became outdated when OpenAI changed its sub-processor list on Oct 14, 2026. Open the replay
  2. 2 Change one input Live recompute · same rules, your change Point /api/crm-sync at Anthropic’s plain Messages API. The server runs the rules again and answer 3 becomes true. The picker under any endpoint tries others. Change it
  3. 3 Try thin evidence A real page with no data-use terms Point /api/crm-sync at Anthropic’s rate-limits page, which says nothing about retention, training or ZDR. Owin marks those answers Not stated for that endpoint. It never invents one. See it marked Not stated

Also: see an answer that needs review, where Owin’s three readings of OpenAI’s page split 2-to-1 on who else sees the data for Responses, so answer 5’s /api/embed cell goes to you for review instead of Owin picking a side.

NVIDIA Nemotron 3 Super, an open-weight model on Nebius Token Factory, read each page three times; this page replays those recorded runs. Code, not the model, decides every answer.

Lumen Notes, its endpoints, settings and trust-page answers are fictional; every vendor sentence, link and fetch time is real. ZDR settings are as the company states them; Owin cannot see vendor consoles. Owin is not legal advice.
